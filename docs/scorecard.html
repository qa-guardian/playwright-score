What we found — and fixed

This card originally read 79/C, FAIL with locators at a flat 0. That wasn’t evidence of raw-selector code — it was a blind spot in the scorer. Every one of n8n’s 256 spec files routes UI interaction through a Page Object Model (n8n.canvas.x, n8n.ndv.x…) defined in separate files the scorer never looked at, so the locator-ratio metric read zero for a suite whose page objects use native locators almost exclusively.

0.1.11 (two days after this report first ran) fixed that: the scorer now follows a spec file’s relative imports to locate page-object files within the scanned directory and folds their locator calls into the suite total, without linting those files as tests themselves. 950 native / 279 raw, locators 0 → 77.

That surfaced a second, related gap: the same tracing needed to recognize class methods, not just free functions — almost every real Page Object Model is a class — and needed to treat .waitFor({ state }) as an assertion, the same way expect(locator).toBeVisible() is one. 0.1.12 added both, plus resolving delegation more than one call deep (n8n’s waitForNotificationAndClose() calls this.waitForNotification(), which calls .waitFor() — two calls removed from anything the original check could see). Files with a missing-assertion finding: ~15 → 5 of 256.

The 5 that remain are a different, smaller pattern — some tests signal failure by throwing directly (e.g. a boot-smoke test that fails on any unexpected console error) rather than asserting a state at all. Left as a known, disclosed gap rather than papered over.

How to read this

Methodology, in short

Real code, not fixtures

Every suite above is scored from a sparse clone of the actual public repository, at the paths and commit noted on each card — not synthetic examples written to flatter the tool.

The published artifact

Every run used the real npm registry package — 0.1.9 for the initial pass, 0.1.11 to verify the n8n fix — the exact thing anyone installing the package gets, never a local dev build.

Standard profile

standard weighs community Playwright best practices (via eslint-plugin-playwright) plus suite-level metrics. No house-specific rules are applied here — see guardian in the README for that layer.

Deterministic, no LLM

The score never calls a model. Same input, same output, every time — re-run any command below and you’ll get the identical number.

$ npx -p @qaguardian/playwright-score@0.1.11 playwright-score examples/todomvc --profile standard
